# reader-v1-examples.txt — Beispiele und Testgrundlage zu docs/protocol/reader-v1.md
#
# Diese Datei prüfen zwei Seiten gleichermaßen: die native Firmware-Testumgebung
# (formatiert Zeilen, wendet den Entpreller an) und der Parser des Box-Dienstes
# (protocol.py). Keine Seite darf von dieser Datei abweichen; bei Streit gilt
# reader-v1.md, und diese Datei wird dann korrigiert.
#
# ALLGEMEIN
#   - Zeilen, die mit '#' beginnen, und leere Zeilen werden ignoriert.
#   - Felder einer Beispielzeile sind durch '|' getrennt. In Beispielzeilen
#     kommt '|' deshalb nie als Inhalt vor.
#   - Escapes in der Spalte <zeile>: \r = CR (0x0D), \xNN = Byte NN (hex),
#     \\ = ein Backslash. Das abschließende LF (\n) steht nie in der Spalte.
#   - Alle Kennungen in dieser Datei sind erfundene Testwerte.
#
# ABSCHNITT 1: Zeilen vom Leser zum Box-Dienst (Parser und Formatierer)
#   OK|<zeile>|zeile=<TYP>|<schlüssel>=<wert>|...
#       Gültige Zeile in kanonischer Form. Der Parser liefert genau die
#       aufgeführten Felder in genau dieser Reihenfolge. Das erste Element
#       zeile=<TYP> ist das Wort am Zeilenanfang und kein Feld der Zeile. Der
#       Formatierer der Firmware muss aus diesen Werten byte-genau diese Zeile
#       erzeugen (Feldreihenfolge wie in reader-v1.md, Abschnitt "Zeilen").
#       Bei ERR steht detail= immer zuletzt und darf Leerzeichen enthalten.
#   OKN|<zeile>|zeile=<TYP>|...
#       Gültige, aber nicht kanonische Zeile (andere Feldreihenfolge, unbekannte
#       Zusatzfelder, CRLF, unbekannter Fehlercode). Bei ERR stehen neue
#       Zusatzfelder vor detail=; steht ein Feld hinter detail=, ist es Teil
#       von detail. Der Parser akzeptiert sie
#       und liefert nur die bekannten Felder in der Reihenfolge der Zeilentabelle;
#       unbekannte Zusatzfelder fehlen in der Auslegung. Die Firmware erzeugt
#       solche Zeilen nie.
#   ERR|<zeile>|<grund>
#       Ungültige Zeile. Der Parser liefert kein Ereignis. <grund> ist einer von:
#         empty_line         leere Zeile (still ignoriert, nicht protokolliert)
#         too_long           mehr als 200 Zeichen (ohne Zeilenende)
#         not_ascii          Zeichen außerhalb 0x20 bis 0x7E (nach Entfernen eines CR am Ende)
#         unknown_type       erstes Wort ist keiner der Zeilentypen (z. B. Boot-Text)
#         bad_syntax         Wort ohne '=', doppelte/führende/nachgestellte Leerzeichen
#                            (auch eine Zeile nur aus Leerzeichen), ungültiger
#                            Schlüsselname, leerer Wert (auch leeres detail=)
#         duplicate_key      derselbe Schlüssel zweimal
#         missing_field      ein Pflichtfeld fehlt
#         bad_value          Wert verletzt Format oder Wertebereich (auch detail mit '|'
#                            oder ';' oder über 80 Zeichen; '|' wird in der Datei als \x7c
#                            geschrieben, ';' als \x3b)
#         bad_uid            uid verletzt den regulären Ausdruck der Kennung
#         uid_type_mismatch  uid, type und tonie passen nicht zueinander
#       Prüfreihenfolge, die erste zutreffende gewinnt: empty_line, too_long,
#       not_ascii, führendes Leerzeichen (bad_syntax), unknown_type, bad_syntax,
#       duplicate_key, missing_field,
#       Wertprüfungen in der Feldreihenfolge der Zeilentabelle (bad_uid bzw.
#       bad_value), zuletzt uid_type_mismatch.
#
# ABSCHNITT 2: Zeilen vom Box-Dienst zum Leser (Befehls-Parser der Firmware)
#   CMDOK|<zeile>|zeile=<TYP>
#       Gültiger Befehl. Die Firmware antwortet wie in reader-v1.md beschrieben.
#   CMDERR|<zeile>|<grund>
#       Ungültiger Befehl. <grund> ist einer von: empty_line (still ignoriert,
#       keine Antwort), too_long, not_ascii, bad_command (jede andere Zeile).
#       Bei allen Gründen außer empty_line antwortet die Firmware mit
#       "ERR code=bad_command detail=...".
#
# ABSCHNITT 3: Zeitabläufe des Entprellers samt Protokoll-Ausgabe
#   SEQ|<name>|<beschreibung>      beginnt einen Ablauf
#   PARAM|confirm_reads=<n>|remove_after_ms=<n>|error_hold_ms=<n>
#                                  Parameter des Entprellers für diesen Ablauf
#                                  (Standardwerte aus timing.h: 2, 1100 und 5000)
#   STEP|<t_ms>|<eingabe>|<ausgabe>
#       <t_ms>: Zeitstempel in ms (vorzeichenlose 32 Bit, monoton, darf überlaufen).
#       <eingabe> ist eines von:
#         nichts                     Abfragezyklus ohne Treffer
#         uid:<typ>:<hex>            gültige Lesung, <typ> = ntag oder iso15693
#         gesperrt                   Tonie im Privacy-Modus, Entsperren gescheitert
#         fehler:<code>              Abfragezyklus mit Fehler (Code aus reader-v1.md)
#         PING                       Zeile "PING" vom Box-Dienst, zwischen zwei Zyklen
#       <ausgabe> ist '-' (keine Zeile) oder die in diesem Schritt geschriebenen
#       Zeilen in der Reihenfolge der Ausgabe, getrennt durch ';' (kommt in
#       Zeilen nicht vor). '*' als kompletter Wert eines Feldes (fw=*, detail=*)
#       passt auf jeden gültigen Wert dieses Feldes.
#       Je STEP gilt: erst die Zeitregel (REMOVED nach remove_after_ms, bei
#       ununterbrochenen Fehlerzyklen nach error_hold_ms), dann die Eingabe
#       (siehe Zustandstabelle in reader-v1.md). Zeilen des Entprellers stehen
#       vor der ERR-Zeile des Fehlerzyklus. seq wird bei jeder
#       Ausgabe von PLACED, LOCKED und REMOVED um 1 erhöht und durch PING auf 0
#       gesetzt; es beginnt nach dem Start bei 0.
#   COUNT|polls=<n>|hits=<n>|rejected=<n>|errors=<n>|present=<0|1>
#       Zählerstände und Wert von present nach dem letzten STEP des Ablaufs
#       (Definition der Zähler: reader-v1.md, Abschnitt "Herzschlag").
#   END                            beendet den Ablauf
#
# Jede Zeile ohne Escape-Zeichen ist exakt so zu lesen, wie sie dasteht.

# unbekanntes Zusatzfeld wird ignoriert (Vorwärtskompatibilität)
OKN|PLACED uid=04a1b2c3 type=ntag tonie=0 seq=1 rssi=40|zeile=PLACED|uid=04a1b2c3|type=ntag|tonie=0|seq=1
OKN|HB up=2 present=0 polls=10 hits=0 rejected=0 errors=0 cycle_ms=58 temp=41|zeile=HB|up=2|present=0|polls=10|hits=0|rejected=0|errors=0|cycle_ms=58
OKN|HELLO proto=1 fw=1.0.0 build=a1b2c3d pn5180=4.2 board=supermini|zeile=HELLO|proto=1|fw=1.0.0|build=a1b2c3d|pn5180=4.2
OKN|REMOVED seq=7 vorgang=x|zeile=REMOVED|seq=7
# andere Feldreihenfolge
OKN|PLACED seq=1 tonie=0 type=ntag uid=04a1b2c3|zeile=PLACED|uid=04a1b2c3|type=ntag|tonie=0|seq=1
OKN|HELLO pn5180=4.2 build=a1b2c3d fw=1.0.0 proto=1|zeile=HELLO|proto=1|fw=1.0.0|build=a1b2c3d|pn5180=4.2
# CRLF am Ende wird entfernt
OKN|REMOVED seq=2\r|zeile=REMOVED|seq=2
OKN|LOCKED seq=9\r|zeile=LOCKED|seq=9
# unbekannter Fehlercode ist gültig (der Dienst behandelt ihn als Warnung)
OKN|ERR code=future_thing detail=something new|zeile=ERR|code=future_thing|detail=something new
# detail darf '=' enthalten, weil es den Rest der Zeile bildet
OKN|ERR code=bad_response detail=cmd=0x04 rc=3|zeile=ERR|code=bad_response|detail=cmd=0x04 rc=3
# neues Zusatzfeld vor detail wird ignoriert; hinter detail wäre es Teil von detail
OKN|ERR code=bad_response rc=3 detail=crc error|zeile=ERR|code=bad_response|detail=crc error
OKN|ERR code=bad_response detail=crc error rc=3|zeile=ERR|code=bad_response|detail=crc error rc=3
